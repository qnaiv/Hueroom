Web 版のプロトタイプです（Vite + React + TypeScript）。

## 起動方法

```bash
npm install
npm run dev        # 開発サーバー（http://localhost:5173）
npm run build      # 型チェック + 本番ビルド（dist/）
npm run preview    # ビルド結果の確認
npm test           # ユニットテスト（Vitest）
```

Node.js 20 以上を想定しています。

### 使い方

1. 「フォルダを選ぶ」で画像のあるフォルダを選びます（jpg / jpeg / png / webp / gif。サブフォルダも対象。`.` で始まるファイルとフォルダは除外）。
2. 解析（主要色の抽出とサムネイル生成）が進むにつれて、色順に並び替わります。結果は IndexedDB に保存されるので、2 回目以降は一瞬で開きます。
3. 並び順は「色」と「日付」を切り替えます。日付は撮影日時（EXIF）の順で、「新しい順 / 古い順」を切り替えられます。
4. 右端のバーをタップ／ドラッグすると、その位置へジャンプします。色モードでは**カラーバー**、日付モードでは**日付タイムライン**（年・月の目盛り）です。タイムラインの目盛りの間隔は、スクロール位置と同じ縮尺なので、写真の多い月ほど間隔が広くなります。
5. 画像をクリックすると拡大表示します（← → で前後、Esc で閉じる）。**お気に入りは拡大表示の星のボタン（または F キー）で登録・解除**します。
6. お気に入りの画像は、サムネイルの右上の角が白い三角（半透明）で塗られます。右端のバーにも、同じ三角が位置を示します。ツールバーの星のボタンで、お気に入りだけに絞り込めます。
7. ツールバーの**「絞り込み」ボタン**で、絞り込みのパネルを開閉します。ふだんは閉じていて、絞り込みたいときだけ開いてチップを押します（閉じていても、効いている絞り込みの数がボタンのバッジに出ます）。パネルの中身は、**画面によって違います**。
   - **日付の画面**: 季節（春 3〜5 月 / 夏 6〜8 月 / 秋 9〜11 月 / 冬 12〜2 月）と、時間帯（朝 5〜10 時 / 昼 10〜16 時 / 夕方 16〜19 時 / 夜 19〜5 時）。撮影日時（EXIF）が無く、更新日時で代用している画像は、絞り込み中は表示しません。
   - **色の画面**: 構図（余白が多い / ぎっしり / 中央 / 左寄り / 右寄り / 上下で明暗 / 左右対称）と、質感（明るい / 暗い / メリハリ / ふんわり / ビビッド / くすみ）。解析が終わっていない画像は、絞り込み中は表示しません。

   同じチップをもう一度押すと解除、「絞り込みを解除」で、いまの画面のぶんをまとめて解除します。チップの数字は、もう一方の行の絞り込みを反映した枚数です。もう一方の画面の絞り込みは、覚えておくだけで、効きません（見えない絞り込みで写真が消えないように）。
8. 拡大表示には、その写真の**配色（パレット）**が出ます。占有率の帯と、色のチップです。**チップを押すと色コードをコピー**します（デザインや絵の配色の参考に）。**「この配色に近い順に並べる」**を押すと、その写真と配色が近い写真が先頭から並びます。ツールバーの「配色が近い順 ✕」を押す（または色・日付を選ぶ）と、元の並びに戻ります。
9. フォルダに画像を追加・削除したあとは、ツールバーの **「更新」** を押します。フォルダを読み直して、新しい画像だけを解析します（解析済みの画像はそのまま、スクロール位置も保たれます）。結果は「3 枚追加・2 枚削除」のように数秒だけ表示されます。Safari / Firefox では、フォルダを覚えられないため、フォルダの選択がもう一度開きます。同じフォルダを選ぶと、同じ動きになります。

### ブラウザごとの違い

| ブラウザ | フォルダの選び方 | 次回起動時 |
| --- | --- | --- |
| Chrome / Edge | File System Access API（`showDirectoryPicker`） | ハンドルを IndexedDB に保存。許可の再確認だけで開ける |
| Safari / Firefox | `<input webkitdirectory>` | 毎回フォルダを選ぶ |

`?adapter=input` を URL に付けると、Chrome でもフォールバック版を強制できます（自動テスト用）。

## 仕組み

### 色抽出（`src/core/color`）

1. 画像を中央の正方形に切り出して 224px のサムネイル（WebP。書き出せない環境では JPEG）にし、そこから 32×32 に縮小します。タイルに見えている範囲の色になります。
2. 32×32 の画素を OKLab に変換し（半透明は除外、白飛び・黒潰れは重みを下げる）、k-means++（k=5、固定シードで結果は決定的）でクラスタリングします。
3. `占有率 × (0.04 + 彩度C)` が最大のクラスタを主要色にします。単純な平均色ではなく、面積が小さくても鮮やかな色が選ばれやすく、全体が低彩度なら最大面積の色になります。
4. 処理は Web Worker（OffscreenCanvas）のプールで行います。使えない環境ではメインスレッドで処理します。

### 構図（`src/core/composition.ts`）

色抽出に使う 32×32 の画素を、そのまま使います（追加のデコードや縮小はありません）。被写体の認識はせず、輝度の勾配（隣の画素との差）と明暗の分布だけから、次の指標を求めて保存します。

| 指標 | 意味 |
| --- | --- |
| `space` | 輪郭の弱い（のっぺりした）画素の割合 |
| `detail` | 輪郭の強さの平均（細かさ） |
| `cx` `cy` | 輪郭で重み付けした重心（0〜1） |
| `vertical` | 上半分の明るさ − 下半分の明るさ |
| `symmetry` | 左半分と、右半分を折り返したものとの差 |

「絞り込み」パネル（色の画面）の**構図のチップ**は、この指標から表示時に決めます（しきい値を変えても再解析は要りません）。「余白が多い」「ぎっしり」は、32×32 では大半の写真がのっぺり側に寄るため、**このフォルダの中での上位・下位 25%** で決めます。「中央」「左寄り」「右寄り」は重心、「上下で明暗」は空と地面のような明るさの差、「左右対称」は折り返した差が小さいものです。複数に当てはまる画像もあります。解析が終わっていない画像は、絞り込み中は表示しません。32×32 なので、細かい構図は拾えない大づかみの傾向です。良し悪しの判定ではありません。

解析結果に指標を足したので `ANALYSIS_VERSION` を 4 に上げました。更新後の最初の起動だけ、保存済みの画像が 1 回再解析されます。

### 質感（`src/core/tone.ts`）

色抽出に使う 32×32 の画素を OKLab に変換して、全体の傾向を 3 つの数値にして保存します（追加のデコードや縮小はありません）。

| 指標 | 意味 |
| --- | --- |
| `brightness` | 全体の明るさ（L の平均） |
| `contrast` | 明暗の差（L の 5〜95 パーセンタイルの幅。ごく一部の白飛び・黒潰れに引きずられない） |
| `saturation` | 色の鮮やかさ（C の平均） |

「絞り込み」パネル（色の画面）の**質感のチップ**（明るい / 暗い / メリハリ / ふんわり / ビビッド / くすみ）は、この指標から表示時に決めます。どれも**このフォルダの中での上位・下位 25%** で決めます（風景ばかり、モノクロばかり、など、フォルダごとに値のばらつき方が違うため）。同じ写真が「メリハリ」と「くすみ」の両方に当たることもあります（白黒でくっきりしている、など）。解析が終わっていない画像は、絞り込み中は表示しません。

解析結果に指標を足したので `ANALYSIS_VERSION` を 5 に上げました。更新後の最初の起動だけ、保存済みの画像が 1 回再解析されます。

### 配色（パレット）（`src/core/palette.ts`）

主要色を決めるときの k-means（k=5）は、写真を 5 つの色に分けています。以前は主要色の 1 色だけを残していましたが、占有率が 3% 以上の色を**パレット**として一緒に保存します（クラスタリングは 1 回のままで、追加の計算はほぼありません）。

配色の近さ（`paletteDistance`）は、片方の各色について、もう片方の一番近い色との OKLab 距離を占有率で重み付けして足し、両方向を平均したものです。色の数が違っても比べられます。主要色が同じ青でも、残りが「橙」の写真と「水色」の写真では、配色は離れます。色の位置（どこに何色があるか）は見ません。

解析結果に配色を足したので `ANALYSIS_VERSION` を 6 に上げました。更新後の最初の起動だけ、保存済みの画像が 1 回再解析されます。

**解析キャッシュ**のキーは `ファイル名 + サイズ + 更新日時` です（`src/core/keys.ts`）。パスを含めないので、上の階層を選び直したり、別のフォルダへ移したりしても、名前・サイズ・更新日時が同じなら解析をやり直しません。解析結果には形式の版（`ANALYSIS_VERSION`）を付けていて、結果に項目を足したときは版を上げます。古い版の保存データは、再解析して上書きされます。

**お気に入り**は、画像の中身の SHA-256（解析時に計算）で識別します。名前の変更、別フォルダへの移動、上の階層からの読み直し、コピー、更新日時の変更をしても、中身が同じなら同じお気に入りとして引き継がれます（同じ中身のファイルが 2 か所にあれば、どちらもお気に入りになります）。リサイズや再保存のように中身が変わる編集をすると、別の画像として扱われ、お気に入りは外れます。ハッシュを計算できない環境（`crypto.subtle` が無い）では、ファイル名・サイズ・更新日時で代用します。お気に入りは、解析が終わった画像から有効になります。

### 並び順（`src/core/sort`）

- **色順**: 彩度が低い画像（C < 0.04）は別グループにして、明度の高い順で末尾に置きます。有彩色は色相で 12 帯に分け、帯ごとに明暗の向きを交互に折り返します（偶数帯は暗→明、奇数帯は明→暗）。帯の中は OKLab 距離の最近傍法で、隣同士の色差を小さくします。1 つの帯が 1,500 枚を超える場合は、計算量を抑えるため明度順にします。解析前の画像は最後に置きます。
- **日付順**: 撮影日時（JPEG の EXIF `DateTimeOriginal`。無ければ `DateTimeDigitized`、`DateTime`）で並べます。EXIF が無い画像（png・webp・gif など）は、ファイルの更新日時で代用します。新しい順 / 古い順を切り替えられます。EXIF の時刻にはタイムゾーンが無いので、端末のローカル時刻として扱います。

- **季節・時間帯の絞り込み**（`src/core/when.ts`）: 並び順とは別の絞り込みです。解析を増やさず、すでに読んでいる撮影日時から、表示のたびに計算します。

### 表示（`src/ui`）

- 色順のときは**蛇行配置**（奇数行を左右反転）で、行の折り返しで色が飛びません（`src/core/layout/snake.ts`）。
- 表示範囲の行だけを描画する**仮想スクロール**です。サムネイルの object URL は、タイルが画面から外れたときに解放します。画像を読み込む前は、主要色で塗ったプレースホルダを出します。
- 解析中の並び替えは 0.5 秒ごとにまとめて反映します。

### 動作確認の結果（ヘッドレス Chromium、ソフトウェア描画）

| 項目 | 結果 |
| --- | --- |
| 2,304 枚（640×480 前後の JPEG）の初回解析 | 約 13 秒 |
| 同じフォルダの 2 回目（キャッシュ） | 約 0.2 秒 |
| 2,304 枚をスクロール中のフレーム間隔 | 中央値 約 17ms、95 パーセンタイル 約 29ms |
| DOM 上のタイル数 | 約 80〜130（全体の枚数に依存しない） |

実機の GPU 環境での計測ではありません。目安として扱ってください。

## ディレクトリ構成

```
src/
├─ core/                  プラットフォーム非依存（共通コード）
│  ├─ color/              oklab.ts（色空間）/ quantize.ts（主要色）/ extract.ts（canvas 処理）
│  ├─ exif.ts             JPEG の EXIF から撮影日時を読む
│  ├─ sort/               hueBands.ts（色順）/ index.ts（日付順）
│  ├─ layout/snake.ts     蛇行配置の対応表
│  ├─ cache/              解析キャッシュ・お気に入り（IndexedDB）
│  ├─ pipeline/           解析キューと Worker プール
│  └─ storage/idb.ts      IndexedDB の最小ラッパー
├─ platform/              ★ プラットフォーム別アダプタ（ここだけ差し替える）
│  ├─ types.ts            FolderAdapter インターフェース
│  └─ web/                File System Access / input フォールバック
└─ ui/                    React（VirtualGrid / NavBar / Lightbox / Toolbar）
```

`core/` と `ui/` はブラウザ固有の「フォルダ取得」API を直接呼びません。`platform/types.ts` の `FolderAdapter` だけに依存します。

## 各プラットフォームへ展開する次の手順

どの場合も、実装するのは `FolderAdapter`（`pickFolder` / `restoreLast` / `listImages`、PC は `watch`）と、`ImageFileRef.getFile()`（実体の遅延読み込み）です。表示・色抽出・ソートは変更しません。

### Web（公開 + PWA）

**GitHub Pages への公開は設定済みです。** `.github/workflows/ci.yml` が `gh-pages` ブランチに公開します。

- **本番**: `main` に変更が入るたびに、テスト → ビルド → ルート（`https://<ユーザー名>.github.io/Hueroom/`）を更新します。
- **PR のプレビュー**: PR を作る・更新するたびに、`https://<ユーザー名>.github.io/Hueroom/pr-preview/pr-<番号>/` に公開し、PR にコメントで URL を貼ります。PR を閉じる（マージを含む）と自動で削除されます。マージ前に、動くものを実際に確認できます。
- **初回だけの設定**: 最初のワークフローが `gh-pages` ブランチを作ったあとで、リポジトリの Settings → Pages → **Build and deployment** → **Source** を **Deploy from a branch**、ブランチを `gh-pages` / `/ (root)` にしてください。
- サブパス配信のため、ビルド時に `BASE_PATH` を渡しています（ローカルの `npm run dev` / `build` は `/` のままです）。


1. `public/manifest.webmanifest` は用意済みです（パスは相対指定なので、サブパスでも動きます）。PNG アイコン（192 / 512px、maskable）を追加します。
2. `vite-plugin-pwa` を入れて Service Worker を生成し、アプリ本体をオフラインでも開けるようにします。
3. 他のホスティング（Cloudflare Pages など）を使う場合は `dist/` を置きます。HTTPS が必要です。
4. Google Fonts を外部から読んでいます。オフライン対応時はフォントを同梱してください。

### Android（Capacitor）

1. `npm i @capacitor/core @capacitor/cli @capacitor/android` → `npx cap init` → `npm run build` → `npx cap add android`。
2. `ACTION_OPEN_DOCUMENT_TREE`（Storage Access Framework）を呼ぶ自作プラグインを書きます。ツリー URI を `takePersistableUriPermission` で保存すると、次回は許可の再確認なしで開けます。
3. `platform/capacitor/` に `FolderAdapter` を実装します。`listImages` は `DocumentFile` を辿って `path / lastModified / size` を返し、`getFile()` は URI から `Blob` を返します（大量の画像は `Capacitor.convertFileSrc` やネイティブ側のサムネイル生成も検討）。
4. 注意: WebView の Worker + OffscreenCanvas は端末の WebView バージョンに依存します。無い場合は `createExtractor()` がメインスレッド処理に切り替えます。

### iOS（Capacitor）

1. `npx cap add ios`。
2. `UIDocumentPickerViewController`（フォルダ選択）で得た URL から security-scoped bookmark を作って保存し、次回はそれを解決して `startAccessingSecurityScopedResource()` を呼ぶプラグインを書きます。
3. `FolderAdapter` は Android と同様に実装します。iOS の WebView（WKWebView）は WebP のエンコードに対応しないことがあります。その場合は JPEG にフォールバックします（実装済み）。

### PC（Tauri）

1. `npm i -D @tauri-apps/cli` → `npx tauri init`。
2. `@tauri-apps/plugin-dialog`（フォルダ選択）と `@tauri-apps/plugin-fs`（`readDir` / `stat` / `readFile`、`watch`）で `FolderAdapter` を実装します。`watch` で変更を検知したら再列挙します。
3. 前回のフォルダのパスは、Tauri の store プラグインなどに保存します。

## 既知の制限

- File System Access 版（Chrome / Edge の `showDirectoryPicker`）は、ヘッドレス環境ではピッカーを操作できないため、列挙のロジックはユニットテストで、画面は `?adapter=input` のフォールバック版で確認しています。実際の Chrome でのピッカーと「前回のフォルダを開く」の動作は、手元で確認してください。
- EXIF の回転は、ブラウザの既定（`createImageBitmap`）に従います。
- GIF は先頭のフレームだけを使います。
- サムネイルはすべてメモリ上に保持します（1 枚あたり 10〜20KB 程度）。数万枚では、必要なぶんだけ読み込む方式への変更が必要です。
